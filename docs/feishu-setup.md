# 飞书准备：用户创建与授权，程序完成建表和同步

## 自动创建完整台账（当前推荐）

用户已在飞书后台创建 KOC Insight 并开通应用身份的多维表格创建权限。
现在只需要安全配置 FEISHU_APP_ID 与 FEISHU_APP_SECRET，运行 `uv run --frozen koc feishu-init` 可创建base和系统表，标识会保存在本地数据库供后续同步复用。
无需事先准备base token/table ID；下文手动创建空白base的流程是可选路线。
创建base结果不明确（如网络超时）时会暂停，禁止盲目重试制造多个表格。
当前Secret绑定和App ID已生效，真实创建与3条笔记写入已完成。标识保存在本地数据库并已添加到环境配置草稿；复用现有台账，不需重复创建。

以下为需要重新配置时的完整说明。无需手工创建几十个字段。

## 1. 创建企业自建应用

登录 [飞书开发者后台](https://open.feishu.cn/app)，创建“企业自建应用”，例如命名为 KOC Insight。
在“凭证与基础信息”查看App ID与App Secret。密钥仅填入云环境安全设置，不发送聊天、不写Git。
无需为了本流程开启消息发送、联系人读取或公网Webhook。

## 2. 开通权限并发布版本

在“权限管理”搜索“多维表格”，为应用开通读取记录、创建/更新记录、读取字段、列出/创建数据表所需权限；使用后台当前显示的权限名称与范围。
版本管理中创建版本并发布；若租户要求管理员审核，待审核通过。无需额外开通通讯录或消息权限。

## 3. 创建空白多维表格并授权应用

在飞书云文档中新建一个空白多维表格，命名 KOC投放台账。
通过文档的应用访问授权入口允许上述应用访问该多维表格并编辑；界面入口可能位于“更多/添加文档应用”或共享/权限设置中，取决于当前客户端。
仅申请API权限不等于已有文档权限。

复制多维表格的base链接；普通形如 `https://<租户>.feishu.cn/base/<app_token>`，其中base后的标识是app_token。若得到wiki链接，先获取其实际多维表格标识，不能把wiki节点token直接代替app_token。

## 4. 在环境安全设置填三项

| 配置名 | 填什么 |
|---|---|
| FEISHU_APP_ID | 开发者后台的App ID |
| FEISHU_APP_SECRET | 开发者后台的App Secret；使用安全密钥输入 |
| FEISHU_BITABLE_APP_TOKEN | 上一步目标多维表格标识 |

FEISHU_TABLE_NOTES_ID可先留空，程序会创建系统数据表后返回它。旧草稿中该字段虽然待填，但初始化命令本身不需要它；如环境编辑器阻止保存，可在UI将这一项暂时移除，后续再填已生成值。
当前配置工具只支持添加变量要求，无法通过代码移除这条旧要求；不要为了绕过校验填写假ID。

## 5. 程序接手

配置实际生效后执行：

```bash
uv run --frozen koc feishu-init-table
```

程序在指定base中创建“KOC笔记台账”和系统字段，不覆盖已有业务表；已有同名系统表则检查结构并复用。
拿到返回table_id后配置FEISHU_TABLE_NOTES_ID，再执行feishu-diagnose和feishu-sync。
以上建表与同步已在真实飞书完成，并与Mock测试结果分别记录；后续更换账号或应用时重新验证权限。
